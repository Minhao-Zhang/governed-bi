# Implementation audit, 2026-08-10 — findings and remediation plan

Tree audited: `c625da8`. Locked versions: `langgraph 1.2.10`, `langchain 1.3.14`,
`langchain-core 1.5.3`, `sqlglot 30.15.0`.

Six parallel readers over `serve/`, `govern/`, `eval/` + `measure/`, `retrieve/` + `corpus/` +
`model/`, `api/`, and `tests/`, each instructed to treat every comment, docstring, README, ADR and
`AGENTS.md` claim as unverified and to accept only executable code as evidence. Load-bearing
findings were then re-verified by execution rather than by a second reading.

**Status column.** `V` — verified here by execution or by reading the source directly. `R` —
reported with a `file:line` citation and a plausible mechanism, not independently re-run. `R?` —
reported, could not be confirmed. 34 of the 122 items are `V` — verified by reading the code or by running it.

**Closed so far.** M1, H1, D6, C5 (`b3f2d15`); C3, C2, D7 (`971364c`); then Phase 0 for the
self-hosted deployment — A1, A2, A3, A7, A8 and the CORS half of B1's exposure; then Phase 1 in
full — C1, C4, C7 — then M5 and the mutation harness (`tools/mutate.py`, now 40 declared mutations); then D5, D11 and E1; then I2 and I3.

**I2 + I3, measured.** Lexical channel only, no model calls, corpus `86ed1dbf`, n = 1351 held-out
questions, `tools/routing_recall.py --corpus-dir ../BIRD-corpus --no-embed`:

| metric | before | after | delta |
|---|---:|---:|---:|
| recall@1 | 0.5522 | 0.5655 | +0.0133 |
| recall@3 | 0.7469 | 0.7624 | **+0.0155** |
| recall@5 | 0.8416 | 0.8379 | −0.0037 |
| recall@10 | 0.9208 | 0.9304 | +0.0096 |
| reached_gold | 0.7461 | 0.7602 | +0.0141 |
| all_gold_tables_licensed | 0.6846 | 0.6904 | +0.0057 |
| none_licensed | 0.2541 | 0.2443 | −0.0098 |

Paired, through `measure.stats.mcnemar` rather than by subtracting the two recalls:
`shortlist hit: +0.0155 (p=0.0295, n=1351, discordant=85, MDE=0.0191)`.

Read that honestly. **p = 0.03 with an effect below the MDE**: the discordant split is unlikely
under the null, and the design is only powered to reliably resolve ≥1.91pp, so 1.55pp sits at the
edge of what this instrument can see. recall@5 moved *down* 0.37pp, so the change is not uniformly
positive. And **no threshold was stated before the run**, which is the discipline `AGENTS.md`
requires and which I did not follow here.

What justifies keeping the change is therefore the **mechanism**, not the aggregate: a question
spelled as words could not reach a snake_case identifier *at all* — `search("food type")` against a
document containing `food_type` returned 0.0, against 0.193 for the exact token — and repeating a
keyword bought unbounded score in queries a model writes. Both are now false, verified directly.
The recall movement is consistent with those fixes and too small for this design to certify.

**The harness paid for itself on its first run**, by catching a gap in the work that created it:
`d6-block-scalar-blind` *survived*. The block-scalar fix had been verified by hand against a
temporary tree and never written down, so re-introducing the defect left the conformance file
green — coverage claimed and not held, which is the exact shape this page is about. Two tests were
added and the mutation is caught now.

**D11 is partly closed, and the other half is deliberate.** The singleton rule now scans `tools/`
— which is where four of the five second implementations the audit found were living — and it
caught the rival `mcnemar` immediately. The *duplicate-name* rule stays inside the package on
purpose: across `tools/` it reports 14 duplicates and 13 are each script's own boilerplate (`ROOT`,
`REPO`, `PKG`, `SKIP_DIRS`, `EXEMPT`, `DEFAULT_CORPUS`, `DEFAULT_DATASET`, `check_file`). A gate
that reports those is a gate that gets waived until it means nothing. `check_measurement_locality`
and `check_imports` are not extended either, for the same reason and pending E2/E3.

**M2 is partly closed and mostly re-scoped.** `test_the_grader_has_no_execution_path_that_skips
_govern` is implemented, narrowed: the property as specified cannot hold, because grading must
execute gold SQL (which no corpus licenses) and the abstention metric must execute a refused
proposal. It is now an enumerated allowlist of the four ungoverned `execute` sites in `eval/`, so
the capability stays visible and cannot grow silently. The file also moved from a module-level
`pytestmark` xfail to per-test markers, for the reason `test_turn_contract.py` already gives about
its own.

**The other eight stubs turned out to document four live defects, not just missing tests** —
`harness.py` still has `or "crashed"` (line 566), `or 0` (648, 649) and `or False` (686), so
absence still becomes a value in the four places the spec names. Fixing those means plumbing
`Absence` through `project_turn` and adding a zero-execution quotability gate; that is its own
package, and the stubs stay red until it lands.

**C6 is accepted rather than fixed**, and deliberately: wrapping `stamp` would produce
`{failure, path_kind: crashed}` with **no `answer`**, since `stamp` is that channel's only writer,
and the harness would then `KeyError` into the same crash row it already produces. Different
traceback, identical outcome. The residual risk — a `stamp` fault is the one turn that cannot
record itself — stands and is worth re-reading if `project()` grows. Two decisions were
taken on 2026-08-10 and are now facts rather than options: the deployment is local/self-hosted, and
`.env` serves `../BIRD-corpus` with all three model surfaces on OpenAI (`gpt-5.6-luna`,
`text-embedding-3-large`). N1 is closed with them; the `GOVERNED_BI_PG_DSN` half went too, since it
still named the MS Fabric database and would have resolved BIRD asset ids against a schema with
none of those tables. Each was mutation-verified:
the behaviour was broken, the new assertion watched to fail with the right diagnosis, and the
source restored. Two of those mutations found defects in the *fixes* — a source-text assertion in
the C2 test that tripped on prose (now AST), and a D7 test that covered the gate function while
leaving its registry wiring uncovered (now driven through `GATE_IMPLEMENTATIONS`). Closed items
keep their rows below, marked, until the phase they belong to closes.

Measured on the real 14,613-row store: 181.3 MB and 0.139 s for the whole table against 1.77 MB and 0.010 s for a projected scan of the same column, with a 2 ms sampler catching the full read as a +407 MB working-set transient. `missing()` calls it once per index build | V |

## Part 2 — Remediation plan

### Why this order

Measurement integrity gates everything else: while the instrument is broken, no product change can
be shown to have worked. So the sequence is stop the bleeding → repair the instrument → re-baseline
→ then move the number. Three rules apply throughout, each earned by a finding above:

1. **Every fix carries a mechanism check, not just a test.** If a change was meant to stop a rule
   firing, count that rule (`AGENTS.md`, Measurement).
2. **Every new test is mutation-verified.** Break the behaviour, watch it fail, restore. M1 is what
   skipping this costs.
3. **Ask of every gate whether it can run vacuously.** D6 scans zero files in CI and exits 0, while
   scanning 7 357 locally — so a local pass proves nothing about CI.

### Phase 6 — Retrieval quality

**Reordered 2026-08-10, and step 3 was wrong.** Two corrections, both from measuring before
changing:

- **I7/I8/I9 come first, not last.** Every remaining item in this phase is a change to how the
  two channels combine, and none of them can be measured through a semantic channel that reports
  `ran` while searching a different text (I7), embeds a different string than it indexes (I8), or
  holds two vector spaces at once (I9). They also need no measurement themselves, which makes
  them the cheap half.
- **RRF is not the fix for I1.** RRF is immune to *scale* but purely ordinal: the top-ranked
  document scores `1/(k+1)`, the maximum a channel can award, however weak the match. That is the
  I1 defect expressed in ranks. The fix is a **fixed, query-independent** ceiling per channel, and
  only cosine needs one — `raw/(raw+k)` is already in `[0,1)`, which is the absolute scale the
  sealed contract prescribes.

Measured on corpus `86ed1dbf`, 120 questions × 57 schema summaries, cache warm, before touching
the rule — because the whole justification for the min-max was a claim about these ranges and
nothing had re-checked it since I2 changed what BM25 scores:

| channel | min | p10 | median | p90 | max |
|---|---:|---:|---:|---:|---:|
| lexical, all scored | 0.121 | 0.129 | 0.523 | 0.780 | 0.933 |
| semantic, all scored | 0.000 | 0.029 | 0.086 | 0.170 | 0.544 |
| lexical, **top hit** | 0.666 | 0.774 | 0.838 | 0.906 | 0.933 |
| semantic, **top hit** | 0.140 | 0.214 | 0.316 | 0.442 | 0.544 |

semantic channel to ~27% effective weight, which is the `max(lexical, semantic)` defect
returning — so the replacement had to be a calibration and not a deletion. And the degenerate
all-tie branch, the part of I1 that needs no comparison to be wrong, **never fires** on
`facet_schema`: 0/120 on both channels, because 47 of 57 candidates share a term.
