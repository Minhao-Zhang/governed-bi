## 2 · B 的判据：深模块 + 实用主义

**定了**　按 `codebase-design` 那套标准（深模块、窄接口、真实的 seam）判断，加你的补充：一个文件就是一个大 script 也可以留，但被多处用到的东西必须提出来。

## 10 · 前后端信号：先全发，事后按 level 分级

**定了**　后端把内存里已有的信号全部 emit 出去，用出经验之后再按 DEBUG / INFO / ERROR 分级。emit 的函数签名第一天就带 `level` 参数（默认 `INFO`）。

**为什么**　你的判断：先用起来才知道什么重要，提前猜没意义。这对 level 这一维完全成立 —— level 是可以事后重新分配的，而且有了参数之后，分级是每个调用点改一个词。

## 12 · 不做兜底，只做记录

**定了**　删掉 `--skip-agent`、`--allow-git-sha-drift`，以及 `_check_resume_manifest` 里「付费跑致命 / smoke 跑只警告」的双轨逻辑。manifest 里多记三个字段：跑的时间、服务器分支 HEAD、对应的 main 分支 hash。不加任何拦截。

**为什么**　你的原话：真跑一定会用 agent、一定花钱；想测试就用便宜模型。所以「不用模型」这个模式服务的是一个不存在的场景。而且默认跑实验的人是有判断力的、能临场调整，不需要为手滑设计。

服务器上有 internal proxy 代码在另一个分支，HEAD 永远不等于 main，所以记 main hash。两个都记是零成本的补充：只记 main 的话，将来 proxy 分支上的改动影响了结果，manifest 里没有任何痕迹能让你想起来。它只是记录，不拦你，不违反「不做兜底」。

**这条同时暴露了一个缺口**　两个 driver 都没有 `--model` 参数，模型只能从 `governed_bi.toml` 的 `[models].llm_model` 读。所以「测试用便宜的、正式用好的」现在的操作是改 TOML —— 忘了改回来不会报错，只会在事后 manifest 里留下一个你没注意的字段。补 `--model`，归进 b1。

**保留的**　resume 的一致性检查。它防的是两套配置混进一份 artifact（产出一个说谎的产物），不是防手滑，不属于兜底。

**否决**　一律硬闸（在服务器上边改边验证时会被绕过，`--force` 最终变成默认）。一律软记录不拦（base commit 没推的话 diff 没有参照物，救不了上次那种情况 —— 但删掉双轨之后这一条实际上就是我们采纳的形态，只是不再区分付费与否）。

## 15 · `retrieval/rvgd.py` 纯拆分，书的设计不在这一轮采纳

**定了（2026-07-30 重定）**　这一轮只做 X.5.1–X.5.9：拆成七个文件、行为逐字节不变、账本上不出现任何 delta。参考书的七项结构性选择（A0 RRF 存废、A1 精确准入池、A2 列级索引、A3 停用词、A4 预算位置、A5 term binding 传播、A6 D 的自积累回路、A7 图遍历）**各自开项、各自基线、各自决定**。书的调参性数字一概不采纳。

**为什么**　拆分本身已经包含七项实测出来的性能与正确性修复，不需要靠采纳书的设计来产生价值：`corpus.by_id` 的线性扫描占热态 `retrieve` 耗时的 **36%**；BM25 有 **76% 的打分花在零词重叠的文档上**；schema 向量没有记忆槽，**每轮 serve 白付 0.814 秒**；而 `oracle_tables_padded` 控制臂因为把 `top_k=8` 当成输出上限（它其实是种子上限，grounding 跑在预算之后）**系统性欠 pad 12%–50%**，`beer_factory` 直接退化回 `oracle_schema` —— 最后这条是 eval 有效性问题，不是重构附带项。

而七项结构性没有一条便宜。详见 [rebuild-checklist.md](rebuild-checklist.md) 的 X.5.10。

**触发这条的事实**　两个文件在抢同一个字母：`retrieval/rvgd.py:5` 说 BM25 是「the 'V'/lexical channel」，`retrieval/embedding.py:1` 说「The V (vector / semantic) channel」。而 `RVGD` 这个缩写在两个仓库、所有文档里从未被完整展开过。

更深的问题是**书的四个字母盖不住我们的五个通道**：

| 字母 | 书里是什么 | 我们有什么 |
|---|---|---|
| R 精确 | 自有池子，命中即入选，不参与排序竞争 | 只有 `fire_triggers`（`triggers.py:18`），仅 `NoteAsset`，regex 触发器未做 |
| V 向量 | 语义召回 | `embedding.py`，真的有 |
| G 图 | AGE 图遍历，depth=3 | `rvgd.py` 里的 grounding 定点扩展，机制不同、目的相同 |

## 16 · 信任边界：受控网络，但 `stream_subgraphs` 破例

**定了**　一次解决四个出口。声明本仓**不提供鉴权**，由部署环境承担；**同时删掉** `/chat` 与 `/corpus/edit` 上那个共享密钥门。读路由不加鉴权。`corpus_release_hash` 保留原样。唯一例外：`stream_subgraphs=true` **在图层封堵**，不靠网关规则。

**为什么**　前三条只是「谁来拦」的分工，网关拦和应用拦效果一样；而那个密钥门只挡两条路，真正执行 SQL 的 `/threads`、`/runs/stream` 完全不经过它，留着它制造的是「已鉴权」的错觉，比没有更糟。

P5 破例的理由不同：`stream_subgraphs=true` 绕过的是 presenter 的**全部脱敏与两轴戳**，也就是绕过治理本身 —— 打开后 `messages` 通道会吐出原始模型 prose、tool_call args 里的原始 SQL、完整 `ToolMessage` 正文（含结果行与 corpus 笔记全文）。而 ADR 0002 的整个论点是「governance = topology, not trust」。**一条写在网关配置里、将来可能忘记同步的规则，不是 topology。**

**顺带落地**　`langgraph.json` 加 `http.cors` 与 `[serve].cors_origins` 同源（或删掉内层那份让配置只有一处）—— 现在实际生效的是外层 `CORS_ALLOW_ORIGINS = "*"` 加 `allow_credentials=True`，内层那份 `localhost:3000` 只覆盖被 mount 的自定义路由。

## 18 · graded delivery 收紧

**定了**　复检传 `allowed_tables`，并把 `term_semantics` 的豁免限定为「不含未授权基表」。执行顺序：**先跑 ledger 回溯查询**（graded delivery 走 `_out_of_band_ledger_entry` 自己写 ledger，generation row 上有 `base_provenance.routed_schemas`，两者若都落盘就是一次离线 join）→ 再写 `tests/test_graded_delivery_scope.py` → 再改。

**为什么**　A6 已经承认行级不设防（`identity` 只写审计行，没有 RLS、没有行级过滤）。如果表级也留一条例外，「governance = topology」就没有可守的边界了 —— 而它是 ADR 0002、也是整个仓库的地基。

新增的一条证据让它更紧：**pooled eval 把 `grade_semantic_failures` 打开了**（`config.py:253` 默认 `False`，`run_datalake.py:4166` 设 `True`），也就是说我们跑得最多的那个臂，正是走 graded delivery 的那条路。

**已知并接受的代价**　graded delivery 会更常拒答，而它存在的全部理由就是「宁可交付一个 `unverified` 也别硬拒」。如果它主要交付的正好是那类无列引用的聚合查询，收紧接近于删掉它 —— 那就该直接讨论要不要保留它，而不是继续加约束。回溯查询的结果会说明这一点。

**否决**　中间态（L4 跑但不阻断）—— 含义是「我们知道越权了，还是发了」，而那次交付带的是 semantic 轴的 `unverified` 戳，越权属于 safety 轴，轴用错了。只改文档 —— 那是在 ADR 0002 的地基上刻一条例外。

## 19 · 跨轮 licensing 列为 non-goal

**定了**　不把上一轮已授权的表并进本轮可授权集。多轮误路由的恢复靠 O1（检索查询拼接上一轮问题）+ O2（覆盖度地板与路由粘性），那两项不扩大任何作用域。

**为什么**　它等于把 agent 上一轮用 `inspect_schema` 拿到的**自授权结果延长一轮**，而 AUDIT S4 收窄的正是这个。可能的辩护是「agent 不能自己扩，系统按上一轮已授权集扩是安全的」—— 站不住，因为上一轮的授权也是 agent 自己拿的。

而且它扩大的是表级作用域，正是决定 18 刚刚收紧的那个唯一守门人。两件事同时开着，就没有一个时刻能说清本轮到底能碰哪些表。
